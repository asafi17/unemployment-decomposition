Pseudo-Out-of-Sample Test for Claims Blindness in High-NE Regimes

Author

Kristin Butcher, Scott Brave, Aryan Safi

Research Question

If claims are less informative about aggregate unemployment when the unemployed pool skews toward ineligible groups, then a claims-only forecasting model should produce systematically larger forecast errors in months when the New Entrants share is elevated, relative to months when it is not. This notebook implements that test as a rolling-origin pseudo-out-of-sample exercise, following the principles in Hyndman & Athanasopoulos, Forecasting Principles and Practice.

Target Variable

The unemployment rate is highly persistent. Forecasting UR in levels lets a claims-only model win by predicting “last month’s UR,” which has nothing to do with claims. Following Hyndman (ch. 9 on stationarity, ch. 5 on benchmarks), we forecast the first difference:

\[ \Delta \text{UR}_t = \text{UR}_t - \text{UR}_{t-1} \]

in percentage points. Forecasting changes is what makes claims-as-leading-indicator interesting: the question is whether a move in claims predicts the next month’s turn in UR, not whether claims help explain the level.

Features

Claims-only model (Model A): lags of \(\Delta \log \text{IC}\), \(\Delta \log \text{CC}\), and two AR lags of \(\Delta \text{UR}\).

Composition-augmented model (Model B): Model A plus lagged NE share.

Benchmarks: random walk (\(\hat{\Delta \text{UR}} = 0\)), AR(1) on \(\Delta \text{UR}\), seasonal naive (\(\hat{\Delta \text{UR}}_{t+1} = \Delta \text{UR}_{t-11}\)).

All models forecast at \(h=1\) using a rolling 30-month training window. Windows that include any month in March 2020 – December 2021 are skipped, as are forecasts targeting those months.

Code 
walk_forward <- function(df, features, target = "dUR", window = 30, label = "model") {
  n <- nrow(df)
  out <- vector("list", n)
  for (end_train in window:(n - 1)) {
    train_rows <- (end_train - window + 1):end_train
    test_row   <- end_train + 1
    if (any(df$pandemic[train_rows], na.rm = TRUE)) next
    if (isTRUE(df$pandemic[test_row])) next

    cols       <- c(target, features)
    train_data <- df[train_rows, cols, drop = FALSE]
    test_data  <- df[test_row,   cols, drop = FALSE]
    if (anyNA(train_data) || anyNA(test_data)) next

    form <- as.formula(paste(target, "~", paste(features, collapse = " + ")))
    mod  <- lm(form, data = train_data)
    pred <- as.numeric(predict(mod, newdata = test_data))

    out[[test_row]] <- tibble(
      date       = df$date[test_row],
      target_val = df[[target]][test_row],
      forecast   = pred,
      err        = df[[target]][test_row] - pred,
      model      = label
    )
  }
  bind_rows(out)
}

rw_forecast <- function(df, target = "dUR", window = 30, label = "RW") {
  n <- nrow(df)
  out <- vector("list", n)
  for (end_train in window:(n - 1)) {
    train_rows <- (end_train - window + 1):end_train
    test_row   <- end_train + 1
    if (any(df$pandemic[train_rows], na.rm = TRUE)) next
    if (isTRUE(df$pandemic[test_row])) next
    if (is.na(df[[target]][test_row])) next
    out[[test_row]] <- tibble(
      date       = df$date[test_row],
      target_val = df[[target]][test_row],
      forecast   = 0,
      err        = df[[target]][test_row],
      model      = label
    )
  }
  bind_rows(out)
}

snaive_forecast <- function(df, target = "dUR", window = 30, label = "SNaive") {
  n <- nrow(df)
  out <- vector("list", n)
  for (end_train in window:(n - 1)) {
    train_rows <- (end_train - window + 1):end_train
    test_row   <- end_train + 1
    if (any(df$pandemic[train_rows], na.rm = TRUE)) next
    if (isTRUE(df$pandemic[test_row])) next
    if (is.na(df[[target]][test_row]) || is.na(df$dUR_l12[test_row])) next
    if (test_row - 12 >= 1 && isTRUE(df$pandemic[test_row - 12])) next
    pred <- df$dUR_l12[test_row]
    out[[test_row]] <- tibble(
      date       = df$date[test_row],
      target_val = df[[target]][test_row],
      forecast   = pred,
      err        = df[[target]][test_row] - pred,
      model      = label
    )
  }
  bind_rows(out)
}

Inference

Block bootstrap on MAE difference (same model across regimes)

For each model, block-bootstrap (block length = 6 months) the difference \(\text{MAE}_{\text{high}} - \text{MAE}_{\text{rest}}\).

Code 
mbb_sample <- function(e, block_len) {
  n <- length(e)
  nblocks <- ceiling(n / block_len)
  starts  <- sample.int(n - block_len + 1, nblocks, replace = TRUE)
  idx     <- unlist(lapply(starts, \(s) s:(s + block_len - 1)))
  e[idx[seq_len(n)]]
}

boot_mae_diff <- function(fc_one_model, B = 2000, block_len = 6) {
  e_h <- fc_one_model |> filter(regime == "High NE") |> pull(err) |> na.omit()
  e_r <- fc_one_model |> filter(regime == "Rest")    |> pull(err) |> na.omit()
  if (length(e_h) < block_len || length(e_r) < block_len) {
    return(tibble(observed_diff = NA, ci_lo = NA, ci_hi = NA, p_two_sided = NA))
  }
  diffs <- replicate(B, {
    mean(abs(mbb_sample(e_h, block_len))) - mean(abs(mbb_sample(e_r, block_len)))
  })
  observed <- mean(abs(e_h)) - mean(abs(e_r))
  tibble(
    observed_diff = observed,
    ci_lo         = as.numeric(quantile(diffs, 0.025)),
    ci_hi         = as.numeric(quantile(diffs, 0.975)),
    p_two_sided   = 2 * min(mean(diffs <= 0), mean(diffs >= 0))
  )
}

Diebold-Mariano: Model A vs Model B within each regime

Does adding the NE share to a claims-only model reduce forecast error, and does the improvement differ across regimes?

Code 
dm_test <- function(err_a, err_b, h = 1) {
  d <- err_a^2 - err_b^2
  ok <- !is.na(d)
  d  <- d[ok]
  if (length(d) < 10) {
    return(tibble(dm_stat = NA_real_, dm_p = NA_real_, n = length(d), mean_loss_diff = NA_real_))
  }
  mod <- lm(d ~ 1)
  nw  <- sandwich::NeweyWest(mod, lag = max(h - 1, 0), prewhite = FALSE)
  ct  <- lmtest::coeftest(mod, vcov = nw)
  tibble(
    dm_stat        = ct[1, "t value"],
    dm_p           = ct[1, "Pr(>|t|)"],
    n              = length(d),
    mean_loss_diff = mean(d)
  )
}

Discussion

The test fails to corroborate the blind-spot story at this horizon. Three findings stand out.

The claims-only model is not detectably worse in high-NE periods. Model A’s MAE is 0.123 pp in high-NE months and 0.119 pp in the rest, a difference of +0.004 pp with a bootstrap 95 percent CI of roughly \([-0.02, +0.03]\) and a two-sided p-value of 0.66. If claims were systematically blind to new entrants in a way that degraded aggregate UR forecasts at \(h=1\), the gap would go the other way and be larger. It isn’t.

Adding the NE share to the claims model doesn’t help. Model B layers lagged NE share on top of Model A. The Diebold-Mariano test on squared errors gives a pooled mean loss difference of \(-0.0004\) pp² (p = 0.54) and small, non-significant differences within each regime. If the blind spot were large enough to show up in month-ahead forecasts, plugging in the very variable that defines the blind spot should improve Model A. It doesn’t.

AR(1) beats the claims models. In both regimes, an AR(1) on \(\Delta \text{UR}\) alone has a smaller MAE (0.107 in high-NE, 0.114 in rest) than the claims-augmented models. The random walk (forecast = 0) is also competitive (0.113, 0.112). At monthly frequency, \(\Delta \text{UR}\) is close to white noise around a small persistent component, and claims add little on top of its own lag. This is a general result, not specific to high-NE months — so it sets a high bar for any story in which claims would help differentially.

What this does not say is that claims are informative about the unemployed pool when new entrants are a large part of it. Representation ratios show — mechanically, from the eligibility rules — that new entrants are outside the IC/CC window. What the forecasting test says is a narrower thing: conditional on how the short-horizon UR process actually behaves, the compositional blind spot does not generate a detectable monthly forecast gap that a claims-based forecaster would have noticed in real time. The blind spot is a level statement about who claims can see; the forecast test is a volatility statement about whether that blindness shows up in the noise of monthly changes. The two are consistent.

One timing observation sharpens the caveat. High-NE months in our sample are concentrated in 2012–2016 (about 57 of 83), with a smaller cluster in 2017–2019 and another starting in 2024. This is mostly the post-GFC recovery: a low-volatility expansion with a subdued claims signal on both sides of the ratio. Any test that demands a big forecast-error gap in that environment is asking for variance the sample does not offer.

Risks & Caveats

  1. Regime imbalance: high-NE months are concentrated in the post-GFC recovery (2012–2016, 57 of 83 months), with a secondary cluster in 2017–2019 and a new cluster in 2024–2025. This is effectively a test of “subdued expansion” vs everything else, not “high-NE cycle phase” vs “low-NE cycle phase.”
  2. Business-cycle confounding: NE share is correlated with the cycle. High-NE periods are typically expansions with lower UR volatility. MASE partially addresses this via a common denominator, but any gap-based test has less power when the base UR is quiet.
  3. Horizon and frequency: \(\Delta \text{UR}\) at \(h=1\) monthly is a demanding outcome — AR(1) already captures most of the predictable variation. A longer horizon or a smoother target (e.g., three-month changes) could reveal differences this test cannot see.
  4. Data vintage: current-vintage (revised) FRED data, not real-time ALFRED. A real-time exercise would also face claims revisions around benchmarks.
  5. Small post-pandemic window: any forecast whose 30-month training window is entirely post-pandemic only starts around July 2024, so post-pandemic coverage is ~1.5 years.
